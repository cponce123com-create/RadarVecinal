Features Faltantes y Mejoras Requeridas
Los siguientes features son necesarios para que RadarVecinal sea un producto viable para municipalidades. Se listan con su especificacion tecnica y prioridad de implementacion.

#	Funcionalidad	Descripción / Especificación Técnica	Prioridad
F-01	Autenticacion JWT	Implementar sistema de auth completo: registro con email+password+DNI, login, JWT tokens con refresh, middleware de autenticacion en todas las rutas protegidas. Usar bcrypt para passwords. El DNI debe ser unico en DB.	CRITICA
F-02	Campo DNI en Schema	Agregar columna dni TEXT UNIQUE NOT NULL a la tabla users en Drizzle schema. Agregar validacion Zod para formato de DNI peruano (8 digitos numericos). Agregar indice unico en DB. Actualizar OpenAPI spec y cliente generado.	CRITICA
F-03	Proteccion de Rutas Admin	Crear middleware de autenticacion y autorizacion por roles (admin, moderator, user). Proteger /admin con rol admin. Proteger endpoints PATCH/DELETE de reports con autenticacion. Retornar 401/403 apropiados.	CRITICA
F-04	Multitenancy por Distrito	Agregar columna district_id a reports, panic_alerts, missing_persons. Crear tabla districts con name, province, department, lat, lng, radius. Filtrar todas las queries por district del usuario autenticado. Preparar para escalar a provincia/departamento.	CRITICA
F-05	Confirmar Reporte	Implementar POST /api/reports/:id/confirm. Tabla report_confirmations con report_id, user_id, created_at para evitar duplicados. Incrementar confirmedCount atomicamente. Mostrar contador de confirmaciones en la UI con boton 'Yo tambien lo vi'.	ALTA
F-06	Upload de Imagenes	Integrar servicio de storage (Cloudinary o AWS S3) para subida de imagenes. POST /api/uploads que retorna imageUrl. Usar en ReportForm y MissingPersonForm. Mostrar preview antes de enviar. Limite de 5MB, solo jpg/png.	ALTA
F-07	Alertas en Tiempo Real	Implementar WebSocket con socket.io o Server-Sent Events para notificaciones en tiempo real de nuevas alertas de panico y reportes criticos. El cliente debe suscribirse al iniciar y mostrar notificaciones toast inmediatas.	ALTA
F-08	Anonimato Server-Side	Forzar isAnonymous=true en el servidor para categorias sensibles (prostitution, drug_point, bar_trouble, informal_commerce) independientemente de lo que envie el cliente. Agregar test que verifique esta logica. Guardar authorName real solo para admin.	ALTA
F-09	Alertas Sonoras por Distancia	Crear servicio de notificaciones con calculo de distancia haversine. Definir radios por categoria (robo: 1km, incendio: 3km, etc.). Usar Web Audio API para sonidos distintos por tipo. Guardar preferencias en localStorage. Solicitar permiso de notificacion al usuario.	ALTA
F-10	Zoom y Navegacion en Mapa	Agregar controles de zoom (+ / -) visibles en mobile. Boton de 'Mi Ubicacion' que centra el mapa con geolocation API. Mostrar nombre de calles en todos los modos (OSM tiles standard). Mejorar nivel de detalle cartografico a zoom 15 por defecto.	ALTA
F-11	Perfil Editable	Agregar formulario de edicion en /perfil: nombre, sector, telefono de emergencia, foto de perfil. PATCH /api/users/:id con validacion. Mostrar historial de reportes del usuario en su perfil con paginacion.	MEDIA
F-12	Paginacion y Scroll Infinito	Implementar scroll infinito en /historial y /alertas usando Intersection Observer. El frontend debe acumular resultados y hacer fetch de proxima pagina al llegar al final. Mostrar spinner de carga y mensaje 'No hay mas resultados'.	MEDIA
F-13	Filtro de Fechas en Stats	Agregar selector de rango de fechas en /estadisticas (hoy, ultima semana, ultimo mes, ultimo ano, personalizado). Pasar dateFrom/dateTo a GET /api/stats. Actualizar graficos dinamicamente al cambiar el rango.	MEDIA
F-14	Gestion de Publicidad en Admin	Completar la UI de gestion de ad_slots en el panel admin: crear, editar, activar/desactivar, ver impresiones. POST/PATCH /api/ad-slots con autenticacion admin. Es parte del modelo de monetizacion para municipalidades.	BAJA
